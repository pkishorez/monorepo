1An Actor is a box

Task
Propsfrom the parent · read-only · always fresh
Inputa starting gift · read once, in init
Modelits own data
Stateits mood: Reading or Editing
Messagesthings that happened · the only way to change
Childrenboxes inside this box
  • Input comes in once, when the box is made. init uses it. Never read again.
  • Props are handed down by the parent, always the latest. Updates and Views read them; only the parent writes them.
  • Model and State change only when a Message arrives.
  • Children exist because the box says so, from its Model, State and Props.
  • A View draws the box from these. That's all a View does.

2Outside work: Workers and Commands

Anything that touches the outside world runs outside the Model. What it learns comes back as Messages; only Messages change the Model.

Worker Command
Runs While its Condition holds, read from the Model. Change the Model, and it starts or stops. Once, when an Update asks for it. Fire and forget.
Sends Any number of Messages while it runs: progress, ticks, socket events, results. At most one Message, at the end.
Can be stopped Yes: change the Model so its Condition no longer holds. No. Only its Instance stopping ends it.
Examples A socket, a timer, an upload with progress, a Route Actor's load Worker Router.push(…), Router.reload(), an RPC save

3History, Snapshot, time travel

History

The list of every Message, in order. A fetched result is inside its Message.

Snapshot

Every box's Model and State, right now. Plain data. Props aren't saved: they're worked out from the parents again.

Time travel

Pick a Message. Kabuki replays the History up to it and draws that Snapshot. No Worker runs, nothing is fetched.

Replay never fetches: the data is in the Messages. Restarting from a Snapshot starts every Worker whose Condition holds, so a fetch that was in flight runs again.

4A route is two Actors: Kabuki's Route Actor, and your page

For every route on the URL there's a pair. Kabuki's Route Actor does the loading. Your page is a normal Actor inside it, and gets the loading status as Props.

Route Actor (Kabuki's; you never write it) Your page (Route.page)
Model load: Loading · Failed { reason } · Ready { data, refreshing } Whatever you want
Input What's already known at the start: the server's data, or the data the Router kept for Back. With data it starts Ready; without, Loading. None. It exists before its data, so there's nothing to hand it at the start.
Workers load: runs while Loading or refreshing; sends Loaded or Failed Yours
Props params, from the Router or the page above params and load, handed by its Route Actor
States, Messages, children Fixed Yours, fully. Child routes are added to its children.
Exists As soon as the URL points at it As soon as its Route Actor exists, even while loading
Your page draws its own loading, error and data from props.load with a switch. That's just drawing Props: no promise, no Suspense, no special screen API.

    Tricky questions

    Do parent and child load one after another?No, at the same time. Both Route Actors exist as soon as the URL points at them, and each one's Worker starts. The child is drawn once the parent page's View places it, which it does in its Ready branch.
    What does the server send?For static/dynamic routes, Start runs the Loaders first and hands the data as each Route Actor's Input, so they start Ready and the HTML is complete. A client route starts Loading, so its page's skeleton is in the HTML.
    Where's the promise for Suspense?There isn't one. Loading is a value in a Route Actor's Model, handed to the page as Props. The View draws it with a switch.
    Why don't pages get Input?Input is read once, when the Actor is created, and a page is created before its data exists. Data that can change belongs in Props.
    What if a page needs an editable copy?An Update sees the Props with every Message, so copy it when it's needed: Edit: (_, { props }) => …props.load.data….
    Back button?The Router keeps each history entry's data. Going back hands it to the new Route Actor as Input, so it starts Ready at once.
    Does a quick click flash a skeleton?No. The Router waits up to 150 ms before switching to the new URL, so a fast load lands straight in Ready. A skeleton that does show stays at least 300 ms.
    One request or many?Route Actors that start loading at the same moment are combined into one request to /_kabuki/load, with Effect's request batching.
