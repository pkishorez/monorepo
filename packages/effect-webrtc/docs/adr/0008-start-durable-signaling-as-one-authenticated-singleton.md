# Start Durable signaling as one authenticated singleton

The Durable Signaling Provider initially routes every browser Peer through one hibernating Durable Object, with Auth Toolkit verifying each WebSocket upgrade and the resulting User identity isolating directory and negotiation operations inside the object. Peer identity and resumable subscriptions live in hibernating socket attachments; the active directory is rebuilt from those subscriptions after a wake, and negotiation messages are never durably queued or persisted. A Durable Object per User would provide stronger physical isolation and scaling, but the singleton keeps the first deployment and routing model narrow; because the provider stores no durable peer or message state, later sharding does not require migrating domain data.
