# Treat signaling as an unreliable provider

The core assumes signaling messages may be delayed, duplicated, reordered, or lost because both WebSockets and Nostr can exhibit those behaviors around reconnects. Connection Intent is therefore durable only inside a live Peer, while each negotiation attempt is identified, expiring, deduplicated, and safe to replace; this keeps Signaling Providers composable without forcing them to emulate a reliable queue. Each Peer Session runs an explicit state machine, and each Connection Attempt owns a child Scope that is closed before replacement. An unanswered Offer expires after `answerTimeout`; an answered attempt gets a separate `establishmentTimeout` to open its Data Channel, after which continuing Connection Intent starts a fresh attempt immediately.
