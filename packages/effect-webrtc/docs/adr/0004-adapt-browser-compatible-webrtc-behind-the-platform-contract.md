# Adapt browser-compatible WebRTC behind the Platform contract

The Browser Platform uses native browser WebRTC APIs behind the existing Platform contract and is published as `effect-webrtc/platform/browser`; the Werift Platform reuses the same browser-compatible adapter and is published as `effect-webrtc/platform/werift` for Node. Importing the Browser Platform does not access browser globals; creating an RTC Connection without `RTCPeerConnection` fails with `RtcError` for `create-connection`. Each RTC Connection owns one ordered, reliable RTC Data Channel labeled `effect-webrtc`; sends wait for the data channel to open, incoming binary values become `Uint8Array`, and text values fail the incoming stream. Because a Signaling Provider can reorder messages, each Platform holds remote ICE candidates until it installs the remote description, applies them in order, and applies remote ICE completion explicitly.
