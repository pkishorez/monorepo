# QA scenarios

QA pass on 2026-10-22, after the UI redesign. Every scenario was recorded at 1440x900 against a fresh database.

## Run it yourself

Build and start the server with `pnpm --filter @kestack/ai-toolkit build`, then `node toolkits/ai-toolkit/bin/ai-toolkit.mjs serve --port 4590 --db /tmp/ai-qa2-db/ai.db`. In another terminal run `pnpm --filter code dev` and open the URL it prints.
Test folders: `/tmp/ai-qa/demo` (README.md, a math.ts with only `add`, package.json) and `/tmp/ai-qa/other` (README.md, notes.txt).
Models: Claude `claude-haiku-5-5` (effort Low), Codex `gpt-5.6-luna` (reasoning effort Low). Scenario 02b uses Claude's default, `claude-opus-5-5`.

## Fixed during QA

- A Claude subagent's "What it reported" ended with Claude Code's note for the model (`agentId: … (use SendMessage …) <usage>…</usage>`). The Claude projection now drops that text block. Files: `toolkits/ai-toolkit/src/harnesses/claude/project/project.ts`, `project.test.ts` (new test).
- A Codex sub-agent's report showed twice: as its last message inside the block and again under "What it reported". The block now drops its last words when they equal the report. Files: `apps/code/src/client/views/project/session/transcript/thread.ts`, `thread.test.ts` (new test), `transcript.tsx`.
- The transcript stopped following new messages after a send. Sending moves the scroller up once while the rows redraw, and that counted as the reader scrolling away. Now only a reader's own gesture (wheel, touch, pointer, keys) lets go. File: `apps/code/src/client/views/project/session/follow.ts`.

## Tool calls redesign

After the streaming pass, tool calls were redrawn: `tools-before-*.png` and `tools-after-*.png` show the same sessions. Transcript text could not be selected at all, because the App Shell's swipe area sets `user-select: none` on the whole page. The transcript now turns selection back on, and a line opens only on a click that selected nothing (or from its chevron button), so dragging over a tool's title selects it. Checked in the browser: dragging over assistant text and a tool title selects it without opening the row, double-clicking selects a word, and copy gives the selected text.

## Known issues

- A Claude subagent's report starts with Claude Code's "[Subagent hand-back] The text below is the final report…" frame, which the projection keeps.
- A Claude edit's diff numbers lines from 1, because the Edit tool sends only the changed snippet, not where it sits in the file.
- Streamed reasoning is never shown live: Claude's thinking blocks arrive empty (only a signature), and Codex's reasoning items have empty summaries at Low and High effort. The reasoning rows and their chunks are covered by `thread.test.ts` only.

- Narrow width, from the shared App Shell (`@kestack/web-platform`): resizing a wide window to 420 px keeps the sidebar open as a sheet over the page; it opens closed after a reload. Escape does not close the sheet; clicking outside does. Both show in scenario 12.
- Claude sessions load your global Claude config (MCP servers, hooks), and Codex reads your global skills.
- Stopping the server logs a stack trace for each open WebSocket (`InterruptError: All fibers interrupted without error`, INFO level, status 499 or 503). This is shutdown noise. No other errors appeared in the server log.
- For Claude, a turn's cost includes subagents but its token counts do not. A turn served from cache can show `$0.000`.
- A Claude Read row shows the full path (`/private/tmp/ai-qa/demo/math.ts`), and a Codex edit row's input is raw JSON above the diff.
