Someone drags "Plan the week" from the work board to home. A task's board
is part of its key, and a key can't change in an update, as [Keyed
entity](/std-toolkit/keyed-entity) said. So a move is two writes: add the
task on home, delete it from work.

If only one of them lands, the task is doubled or lost. This page saves
both as one.

## All or nothing

A **transaction** saves several writes together. Either every one lands,
or none of them does.

## Prepare, then commit

Every write you've used has a twin that prepares it without saving it:
`insertOp`, `getAndUpdateOp`, `deleteOp` and `restoreOp`. Each gives back
an **op**. `table.transact` then saves a list of ops as one:

```ts file=./components/tasks.ts

```

Every write in a transaction gets the same update stamp, `_u`. So a device
that syncs later sees the move as one change, not two.

When a transaction is refused, it fails with a `TransactFailed` reason
that says which op refused, and why. Nothing is written.

## Checks

Sometimes a batch depends on a row it doesn't change: "add this task, but
only if its board isn't archived". A check op asserts something without
writing anything:

- `getAndCheckOp(key, (current) => …)` holds when your function says so.
- `existsOp` and `notExistsOp` hold when the row is there, or isn't.
- `unchangedOp(entity)` holds when nobody saved that row since you read
  it.

If a check fails, the whole batch is refused, just like a refused write.

## The same limits everywhere

A transaction follows DynamoDB's rules, on every adapter: at most 100
ops, each row at most once, and every op from the same table. Break one,
and it's refused before anything is written, even on Memory. So a batch
that works in your tests works in production too.

## scan

One more call that works on the whole table. `table.scan()` streams every
row it holds, of every kind, exactly as stored. The rows are untyped,
since no one shape fits them all. It's what a backfill walks, as [Drift
and reindex](/std-toolkit/drift-and-reindex) showed, and it's how the Live
Tables on these pages draw their left column.
