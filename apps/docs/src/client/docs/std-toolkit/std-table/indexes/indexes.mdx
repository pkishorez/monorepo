A query reads one partition, in sort key order. For tasks, that's one
board, by id. But your app has other screens: the board sorted by title,
and a "today" list of every high-priority task, on any board. This page
gives you both, from the same table.

## What an index is

An **index** keeps the same rows a second time, under other keys. The
database updates it on every write, so it's never out of date for rows
you save from now on.

There are two kinds, and the difference is the partition:

- A **local secondary index**, or LSI, keeps the partition and sorts by
  something else. "This board, by title."
- A **global secondary index**, or GSI, has a partition of its own, so it
  reaches across boards. "Every high-priority task."

## Two steps: slots, then names

Adding an index takes two steps, on two different things.

First, **the table declares slots**: numbered places for indexes, with the
names of their key columns.

```ts
const table = StdTable.make('board')
  .primary('pk', 'sk')
  .lsi('LSI1', 'LSI1SK')
  .gsi('GSI1', 'GSI1PK', 'GSI1SK')
  .build();
```

The names are generic on purpose. `LSI1` says nothing about titles,
because many kinds share the table, and each uses a slot its own way.

Then **each entity names what a slot means for it**. That name is an
**access pattern**, and it says which of the entity's fields make the
keys:

```ts
const task = table
  .entity(Task)
  .primary({ pk: ['boardId'] })
  .index('LSI1', 'byTitle', { sk: ['title'] })
  .index('GSI1', 'byPriority', { pk: ['priority'], sk: ['boardId', 'title'] })
  .build();
```

`byTitle` uses the LSI, so it only names a sort key: the partition is
still the board. `byPriority` uses the GSI, so it names both. Its sort key
has two fields, so the tasks come back by board, then by title.

## Querying by name

You query an access pattern by its name, just as you did `'primary'`:

```ts
task.query('byPriority', { pk: { priority: 'high' }, '>=': null });
```

The types follow the pattern. `byPriority` wants a `priority` in `pk`,
and TypeScript tells you if you pass a `boardId` instead.

A sort key made of several fields can be narrowed by its first ones.
`beginsWith` matches a prefix, so this is "high priority, on the work
board". The empty title means any title:

```ts
task.query('byPriority', {
  pk: { priority: 'high' },
  beginsWith: { boardId: 'work', title: '' },
});
```

One thing to know when you pick a database: on DynamoDB, a GSI read is
eventually consistent. A task you just saved may take a moment to show up
in `byPriority`. Memory, SQLite and IndexedDB see it at once.

<Callout title="Remember">
  The table declares index slots; each entity names its own access patterns on
  them. An LSI reorders a partition; a GSI regroups the whole table.
</Callout>
