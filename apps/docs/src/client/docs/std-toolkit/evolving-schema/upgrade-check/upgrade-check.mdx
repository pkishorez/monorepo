Every change you've made so far rests on one promise: each row an old
version could have stored still reads in the new one. A migration is that
promise, written as a function. This page shows the test that checks it,
before a user finds the row that breaks it.

## The row you didn't think of

On the last pages you met the risky change: an estimate kept as text
becomes a number. You write the migration with `'3'` and `'0.5'` in mind.
It works on every row you try.

Then a user who once typed `a` opens their board, and that task fails to
read. Your migration was right for every row you thought of. It was wrong
for one you didn't.

## The upgrade check

The **upgrade check** doesn't wait for that user. For each version of a
schema, it generates many values that version could have stored, stores
each in that version's encoded form, and reads it at the latest version.
When a row fails, it shrinks it to the smallest row that still fails.

<Picture caption="Each generated v1 row goes through the migration. Numbers read fine. The first one that fails stops the check, which names the version and the smallest stored row that shows it.">
  <CheckPicture />
</Picture>

A row fails the check when:

- its migration throws, or returns a value the latest version refuses;
- its id changes on the way;
- it doesn't read back the same after it's saved again.

Shapes nested inside are checked too, each at every one of its versions.

## In your tests

In a test file, write `expectUpgradable`. It runs the same check and fails
the test with the same report, in any test runner:

```ts
import { expectUpgradable } from '@kestack/std-toolkit/eschema/testing';

it('reads every stored task', () =>
  expectUpgradable(Task, { unchanged: ['boardId'] }));
```

`unchanged` names fields no migration may change. A task's `boardId`
decides where it is kept, so a migration that changed it would leave the
row stranded at its old place. You'll see why in [Keyed
entity](/std-toolkit/keyed-entity).

You'll rarely call it yourself, though. Once your shapes live in a table,
its [Snapshot](/std-toolkit/snapshot) test runs this check for every shape
in it.

<Callout title="Remember">
  A migration must work for every value the old version could hold, not just the
  ones you tried. Let the upgrade check find the rest.
</Callout>
