ESchema and EntityESchema version an object, with named fields. Each
version adds or takes away fields, and the stored object carries its `_v`
beside them. But some things you save aren't objects. Your app's theme is
one word. This page versions a value like that.

## A value with versions

A **ValueESchema** versions one value: a string, a number, an enum, a
list, a map or a union. You make it from any Schema, and `evolve` it the
way you already know.


In v1 the theme was free text: whatever the user typed. In v2 it is one of
two words. The migration gets each old text and picks a word for it.

One thing differs from an object's version. There are no fields to add or
remove, so each version gives the **whole** new Schema, not a delta.

## The envelope

An object has room for `_v` beside its fields. A bare string doesn't. So a
ValueESchema stores its value in a **value envelope**: `{ _v, _value }`,
the value with its version beside it.

</Picture>

Reading works as it does for an object. The envelope's `_v` says which
version wrote it; the value is read at that version and migrated up to the
latest. Your code only ever sees the bare word, `'light'` or `'dark'`.

A value with no envelope at all reads as v1. So a theme saved as plain
text, before you versioned it, keeps working. There's nothing to backfill.

## Which one to pick

Pick by what you are versioning:

| You're versioning                          | Write           |
| ------------------------------------------ | --------------- |
| A thing you keep many of, each with an id  | `EntityESchema` |
| An object with named fields, and no id     | `ESchema`       |
| A word, a number, a list, a map or a union | `ValueESchema`  |
| An older object that has optional fields   | `ValueESchema`  |

The last row is a way out. An ESchema refuses optional fields, so every
version has one exact shape. A ValueESchema wraps any Schema, so an older
object with optional keys can still be versioned, as a whole.

<Callout title="Remember">
  A ValueESchema versions a whole value, not fields. Its value is stored in an
  envelope, `{ _v, _value }`, so it can carry its version.
</Callout>
