Every demo in these docs has quietly run on one adapter: Memory. It is the
simplest home a table can have, and the right one for tests, stories and
demos. This page shows what it promises, and what it doesn't.

## Nothing to set up

`Memory.make(table)` gives you an empty table, ready at once. It takes no
config, no database name and no mode: nothing outlives it, so there is
nothing a change could break.

That's all the code a Memory table needs. The query at the bottom runs on
whatever layer you provide; on this page, a Memory one.

## One call, one table

Each `Memory.make` call is a new table of its own. Reuse its layer and you
share its rows; call `Memory.make` again and you start from empty. When
nothing holds the table any more, its rows are gone.

That is why each test can make its own table and never see another test's
rows. It is also why a reload empties every demo on this site: the page
made a new Memory table when it loaded.

A delete keeps the row, marked deleted: a **tombstone**. A query returns
tombstones too, unless you pass `excludeDeleted`, as this one does. Every
adapter keeps them, so that when you [sync](/std-toolkit/how-sync-works),
other copies can learn the task is gone.

<Callout title="Remember">
  `Memory.make(table)` is a fresh, empty table that needs nothing and keeps
  nothing. Share its layer to share its rows; make another for a clean start.
</Callout>

Memory forgets everything when the page goes. Next,

across reloads.
