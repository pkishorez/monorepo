You can save, find and change tasks and settings. But a screen showing the
work board doesn't know when a task changes. This page closes that gap:
you listen to an entity, and hear every save as it's saved.

## Hearing about saves

Without help, you'd keep the list in state and remember to refresh it after
every write. Miss one place that writes, and the screen is stale.

So you **subscribe** instead. Each saved write sends a **Change Notice** to
everyone listening. A notice is the same Entity the write gave back: the
`value`, and its `meta`.

  <NoticePicture />
</Picture>

Notices come only from writes that were saved. A refused insert is never
announced, so a subscriber never sees something that didn't happen.

## subscribe

Every entity has `subscribe`. It returns an Effect `Stream` of notices:

```ts
task.subscribe({ boardId: 'work' });
```

The filter is optional. It matches fields exactly, typed to your shape,
so `{ boardId: 'work' }` hears only that board. Leave it out to hear every
task.

A delete is a notice too. It arrives with `meta._d` set to `true`, since a
delete is a tombstone, not a gone row. A single entity's `subscribe` works
the same way, for its one record.

## The Broadcaster

Notices travel through a **Broadcaster**. You provide one beside your
table's layer:

```ts
program.pipe(Effect.provide(memory.layer), Effect.provide(defaultBroadcaster));
```

`defaultBroadcaster`, from `@kestack/std-toolkit/db`, delivers notices
inside one process. When several participants write to the same storage,
like every tab on one IndexedDB database, `sharedBroadcaster` lets each
hear the others' writes.

It's optional. Without one, writes still save, and `subscribe` gives a
stream that never yields. Notices are fire and forget: a subscriber that
starts late doesn't get the ones it missed.
