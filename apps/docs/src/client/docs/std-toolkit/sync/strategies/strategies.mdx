A Collection reads the Backend through a **Sync Strategy**. It decides two
things: in what order the copy fills in, and when it asks again. This page
shows the two built in, the one rule every fetch must keep, and how to load
only what's on screen.

## Oldest first, or newest first

`strategy.oldToNew` reads from the oldest change forward, a page at a time,
then keeps asking for anything newer. `strategy.newToOld` shows the newest
page first, then fills in older pages behind it, while keeping the top
fresh.

Pick `oldToNew` when you need everything, like a board's tasks. Pick
`newToOld` when the newest matters most and the rest can wait, like a feed or
a chat.

## The cursor rule

A strategy hands your `fetch` its cursor as `after`: the newest Entity read
so far, or `null` the first time. Return only what comes **strictly after**
it, oldest first. Filter with `>`, never `>=`.

```ts
const fetch = ({ after }) =>
  api.tasksChangedAfter(after === null ? null : after.meta._u);
```

Why so strict? With `>=`, every page starts with the last page's final task
again. Sync notices the cursor isn't moving and stops, but you've paid for a
page you already had.

Run it to watch the pages. Each one starts where the last one ended, until a
page comes back empty. Then the same fetch with `>=` repeats a task.

`newToOld` keeps the same rule the other way: its `fetchOlder({ before })`
returns only what is strictly before.

## Pulling, or being pushed

`oldToNew` can read three ways:

```ts
// Pull: catch up page by page, then ask again every five seconds.
strategy.oldToNew({ fetch, pollEvery: '5 seconds' });

// Pushed: the Backend replays everything after the cursor, then streams.
strategy.oldToNew({ subscribe });

// Both: catch up by pulling, then stay live on the feed.
strategy.oldToNew({ fetch, subscribe });
```

Without `pollEvery`, a `fetch` catches up once and stops. If a feed drops, it
opens again from the saved cursor, so nothing is missed.

## Only what's on screen

A strategy under `global` covers the whole Collection while it's mounted. You
can instead give one per **Window**: the rows whose key reads one value, like
the tasks of one board.

```ts
const tasks = app.collection(Task, {
  sync: {
    windows: {
      boardId: (boardId) =>
        strategy.oldToNew({
          fetch: ({ after }) => api.changesOn(boardId, after),
          pollEvery: '5 seconds',
        }),
    },
  },
});
```

A Window opens when a query filters on its key with `eq`, and its strategy
runs while that query is there. When the last one leaves, the strategy
stops, and the rows stay. So a board you opened once still shows offline.

| You give  | It is           | It loads                                    |
| --------- | --------------- | ------------------------------------------- |
| `global`  | **Eager**       | Everything, once the Collection mounts.     |
| `windows` | **On-demand**   | Only what a query looks at.                 |
| both      | **Progressive** | What a query looks at first, then the rest. |

## A Backend that's a little late

Some Backends make a write readable a moment after its `_u` was made, from
replica lag or parallel writers. A cursor that already moved past it would
skip it for good.

Set `settleWindow: '5 seconds'` on the Collection. The built-in strategies
then never save their cursor past the newest `_u` read minus five seconds,
so each poll reads the last five seconds again. Repeats are ignored, since a
newer `_u` wins. It's off unless you set it.

## Your own

`strategy.make` builds a strategy from a name, a state schema, a starting
state, and a `run` that yields Entities with the next state. Each yield is
stored in one write, so a reload resumes where it stopped. The built-in ones
are made the same way.

<Callout title="Remember">
  Return only what's strictly after the cursor. Use `global` for everything,
  `windows` for what's on screen, or both.
</Callout>
