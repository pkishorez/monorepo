People open your app in three tabs, close the laptop, and come back on a
train with no signal. This page shows how one copy serves every tab, how
it opens offline, and what happens to an edit that can't be saved.

## Where the copy lives

By default a Std Sync keeps its copy in memory: gone on reload, and each
tab reads on its own. Give it a **Sync adapter** to choose a better place.

```ts
import { createStdSync } from '@kestack/std-toolkit/sync';
import { Sync } from '@kestack/std-toolkit/sync/idb';

const app = createStdSync({ name: 'board', store: Sync.idb() });
```

`Sync.idb()` keeps the copy in IndexedDB, shared by every tab of your app
in this browser. Now the copy outlives a reload, and the tabs agree.

## One tab reads for all

If every tab polled the Backend, three tabs would cost three times as
much. So each reading job, the global strategy or one Window's, has its
own **Leadership**: one tab holds it, and the others wait.

The tab that leads stores what it reads in the shared store, then rings
the **Doorbell**. Every tab hears it and reads that Collection again from
the store. The Doorbell carries no rows; it only says "look again".

When the leading tab closes, another takes over from the saved cursor. And
different tabs may lead different Windows.

`Sync.idb` uses Web Locks for Leadership and a BroadcastChannel for the
Doorbell. Where a browser lacks one, it falls back to none, and every tab
reads for itself.

## Offline

A Collection opens from its copy before any network call, so the board is
there at once, even with no signal. Each strategy resumes from its saved
cursor.

When a fetch fails, it tries again after a growing delay, and the copy
stays on screen. Once the network is back, reading picks up where it
stopped.

An edit is different. A Mutation Callback calls the Backend directly. If
it can't, the edit is rolled back, rather than shown as saved when it
isn't. Writes that wait offline and send later aren't in this version.

## An app newer than this tab

Say you ship a v3 of `Task` while an old tab is still open. That tab reads
a v3 task it doesn't know how to read. That's an **Outdated Application**:
not an error. Sync skips the task, reports it once, and stops reading that
scope until a reload brings the new code.

## Signing out

Nothing is deleted on its own. Put the user's id in the Std Sync's name,
so one person never sees another's rows. On sign-out:

```ts
await app.dispose();
await Sync.idb.remove(`board:${userId}`);
```

`Sync.idb.list()` lists every Std Sync stored in this browser. On a shared
or sensitive device, use `Sync.memory()`, and nothing touches the disk.
