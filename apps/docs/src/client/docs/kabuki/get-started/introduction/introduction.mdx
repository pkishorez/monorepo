Everything in kabuki starts with an **Actor**.

In React, a component is the building block of your UI. In kabuki, an Actor
is the building block of your logic. It holds some data, it listens for
Messages, and it decides what each Message means. React is left with one
job: drawing what the Actors hold.

## The loop

Every kabuki app runs the same small loop, again and again.

<Picture caption="A press becomes a Message. The Actor's Update makes the next Model. React draws it. Nothing else changes anything.">
  <LoopPicture />
</Picture>

The button doesn't change the count. It sends a Message, `Incremented`, and
the Actor decides what that means. Since every change goes through a
Message, kabuki can keep them all. So you can see your app as it was at
any moment, and carry on from there.

## Four parts

kabuki comes in four parts, and you read them in order. Each is its own
import path, and each uses only the ones before it. An app takes as many
as it needs, starting from core.

- **core**, `@kestack/kabuki`: the Actors and how they run. It starts at
  [Actor](/kabuki/actor).
- **react**, `@kestack/kabuki/react`: drawing them with React. It starts at
  [View](/kabuki/view).
- **routing**, `@kestack/kabuki/routing`: giving them a place in the URL.
  It starts at [Pages](/kabuki/pages).
- **start**, `@kestack/kabuki/start`: serving them as one app. It starts at
  [Serving](/kabuki/serving).

## If you know React

You already know most of kabuki. Most of its ideas have a twin in React.
Here they are, each with the part it is in.

<ReactTwins />

The difference is where things live. In React, logic hides inside
components, spread across hooks. In kabuki, the logic is one tree of
Actors, outside React, and you declare all of it. What you write down is
what runs.

## When to use it

kabuki fits apps where the hard part is logic over time: syncing,
uploads, sign-in flows, anything that starts, stops and fails. It is more
than you need for a page that only shows data from a server.
