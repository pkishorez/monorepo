In React, you build a UI out of components. In kabuki, you build your logic
out of **Actors**. Everything else in these docs is something an Actor can
do.

## What is an Actor?

An Actor is a small piece of your app that holds some data and reacts to
what happens. It has three parts:

- a **Model**: the data it holds, like `{ count: 0 }`;
- **Messages**: the things that can happen to it, like `Added`;
- an **Update**: what each Message does to the Model.

That's it. Nothing outside can reach in and change the Model. The only way
to change an Actor is to send it a Message, and let it decide.

If you've used `useReducer`, this will feel familiar. The difference is that
an Actor lives outside React, so your logic doesn't depend on what is on
screen.

Making an Actor takes two steps: you define it, then you build it.

## 1. Define it

The **Definition** says what the Actor is: its name, the shape of its
Model, and the Messages it takes. Each shape is a Schema.

```ts
export const Counter = Actor.define('Counter', {
  model: Schema.Struct({ count: Schema.Number }),
  message: Schema.TaggedUnion({
    Added: { amount: Schema.Number },
    Reset: {},
  }),
});
```

Why a separate Definition? Because every type in your app flows from it.
The Update, the button that sends `Added`, the parent that holds a Counter,
your tests: TypeScript checks all of them against this one place. Forget
the `amount`, and it doesn't compile.

The Schemas also check at runtime. A Message that doesn't fit, like an
`amount` of `'ten'`, is refused before anything sees it.

And a Definition runs nothing. So anything can import it, a parent, a View
or a test, without pulling in the logic behind it.

## 2. Build it

The **Build** says how the Actor behaves: where it starts, and what each
Message does.

```ts
export const CounterLive = Actor.build(Counter, {
  init: () => ({ model: { count: 0 } }),
  on: {
    Added: ({ amount }, { model }) => ({
      model: { count: model.count + amount },
    }),
    Reset: () => ({ model: { count: 0 } }),
  },
});
```

Each Update gets the Message and the current Model, and returns the next
Model. It's a plain function. It doesn't fetch, wait, or touch anything
else, so it's easy to read and easy to test.

By habit, the Build is named after the Actor with `Live`, and sits beside
its Definition.
