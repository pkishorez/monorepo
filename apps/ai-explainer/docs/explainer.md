# Explainer Format

How every Explainer is built. Change it through `/explainer` when a Pick
should apply to all future Explainers, not just one.

## Purpose

Teach one core idea through one clear visual story, not a list of facts, to
working developers. The idea may be a package of this monorepo or any topic
behind it, such as single-table design in DynamoDB. 75 to 90 seconds.

## Arc

Seven Scenes, each adding new understanding:

1. **hook**: the tension, in under 5 seconds.
2. **familiar-world**: how things work today.
3. **disruption**: what goes wrong.
4. **mechanism**: how it works.
5. **discovery**: the moment it pays off.
6. **consequence**: what changes for the viewer.
7. **recap**: the idea in one breath.

## Narration

- Warm and precise. Concrete language before technical terms.
- Written for 125 to 145 words per minute.
- Never repeats the text shown on screen; labels stay brief.

## Pacing

- Something meaningful changes on screen at least every 4 seconds.
- One main visual idea per shot; let key transformations breathe.
- No hard cuts: a visible object becomes the next Scene.

## Files

```
src/explainers/<name>/
├── index.ts         re-exports the Explainer
├── <name>.tsx       its Scenes, joined with defineExplainer
├── script.ts        one narration line per Scene
├── voiceover.ts     generated by `pnpm voiceover <name>`
└── voiceover/       generated audio, committed
```

A new Explainer is also added to `src/studio.tsx` and as a module in
`laymos.config.json`. An Explainer is finished once rendered (ADR 0003).
