# Files are shown through a files Plugin, and only where the agent writes a File Embed

Status: accepted.

A Session's agent often makes something to look at: a chart as HTML, a screenshot, a video. Code shows it through a second Plugin, `files`, which knows nothing of Sessions: given a base folder and a path, `requestFile` resolves it, follows its symlinks, and answers with its kind, MIME type and size and a File Ticket, or why it cannot (Missing, NotAFile, Unsupported, Unreadable). A File Ticket is a random 256-bit token in the Plugin's Public Area, `/files/public/<token>/<filename>`, bound to the file as it was when given, kept only in memory, and gone an hour after it was given however much it is used; anything else there is a 404. The kind comes from the extension of the file the path really is, its symlinks followed, so a symlink with a showable name that points at a file of another kind is Unsupported; a hard link is not caught, but making one takes access to the file already. The kinds are images, video, audio, PDF, HTML and markdown, sent with a fixed MIME type, `nosniff`, `Range`, no referrer, and `Cache-Control: private, no-cache` with an ETag and Last-Modified, so a browser checks with the Plugin before it reuses what it kept, and a file written again is sent again. A page reuses an image it has decoded for the same URL, so Code asks for a ticket of its own for each Message a file is embedded in. The Public Area is reached by `<img>`, `<video>`, `<iframe>` and navigation, which send no Origin; a `fetch` from an origin not on the Connection's list, a sandboxed page's `null` among them, is refused by the Connection's Origin check before it reaches the Plugin. HTML and SVG run sandboxed with no same-origin, so a page may load scripts from a CDN but never call the Connection. There is no list of refused folders: whoever holds the Connection Key can already read anything, and most files that hold secrets, keys, `.env` files and the like, have no kind the Plugin shows. Markdown and HTML can hold secrets in plain text too; they are shown by choice, as what an agent most often writes to be read. Code shows only File Embeds, `![caption](files:<path>)`, which the `code` Plugin tells every Session's agent to write, through a new instructions option in ai-toolkit; Code sends the Session's Worktree, or its Project's folder, as the base, asks as each comes into view, keeps each answer, for the Message it is embedded in, until five minutes before an hour after it arrived, by its own clock, and opens its own viewer when one is clicked.

## Considered options

- **The `code` Plugin gives and serves the files.** Rejected: showing a file is the same for any App, and a Plugin that knows nothing of Sessions is one any App can use.
- **Code finds paths in any text, links and tool calls.** Rejected: most would ask for files that are no use to show, and an agent writing a path to a file would be enough to put it on screen. A File Embed is one the agent wrote on purpose.
- **The kind found from the file's first bytes.** Rejected for now: the extension, with a MIME type the Plugin sets and the browser told not to guess, is enough.

## Consequences

- Code holds a second socket to each Connection, to the `files` Plugin, at the Release it was built with.
- A Plugin update ends every File Ticket; Code asks again on a 404.
- Every plain-text kind shown can show a secret written in it. Markdown and HTML already do, by choice; adding `.txt`, `.json` or any other plain-text kind widens that, so it is a choice to weigh the same way, or to make with a list of refused folders brought back.
