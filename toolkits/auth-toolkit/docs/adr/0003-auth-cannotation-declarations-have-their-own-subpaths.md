# Auth Cannotation Declarations have their own subpaths

> Names changed since this was written ([ADR 0005](../../../../docs/adr/0005-three-toolkits-three-doors.md)): the doors are now `worker`, `worker/memory`, `worker/alchemy`, `guard`, `server`, `server/cloud`, `client`, `client/web`, `client/expo` and `client/cli`; Cannotation is Middleware; `CurrentAuth` is `Authz.Current`, `VerificationUnavailable` is `Authz.Unavailable`; `authzLayer` is `authz.layer`, `authzCookies` is `authz.cookies`, `resolverLive` is `authz.cloud`, `resolverLocal` is `authz.device`; the `Auth` service is `SignIn`, `authLive` is `cookie` (from `client/web`), `authExpo` is `oauth`, `authLocal` is `signIn.named`, `CliAuth` is `DeviceCode`; a Local Account is a Named Account and a Local Token a Name Token; better-auth's session is a Sign-in, and Session means only the app's.

The Auth Cannotation for each Sibling is declared with rpc-toolkit's `Cannotation.make`, and rpc-toolkit's ADR 0001 requires a Declaration to be importable from contract code shared with the browser. auth-toolkit therefore exposes `@kstackz/auth-toolkit/rpc` and `@kstackz/auth-toolkit/http-api` as Declaration doors, each exporting the single `Authz` object and keeps a server subpath for the Server Implementation (`authzLayer`, `resolverLive`, and for RPC `authzCookies`), with no symbol on both doors and no standalone type exports. We rejected one door per Sibling because it drags the Auth Worker verifier and better-auth runtime into the contract bundle; better-auth's `User` and `Session` remain as type-only imports in the Declaration since consumers already depend on better-auth for the Auth Worker. Each Declaration is its own module (`src/server/effect/rpc/declaration`, `src/server/effect/http-api/declaration`) beside its Server Implementation module, so Laymos checks that a Declaration never imports server code. The Server Implementation subpaths are `@kstackz/auth-toolkit/server/rpc` and `@kstackz/auth-toolkit/server/http-api` since [ADR 0013](./0013-one-auth-worker-contract-three-program-graphs.md). `Authz` carries `guard`, `policy`, `CurrentAuth`, `Resolver` (the tag tests replace; its production layer is `resolverLive`), and the three errors (`Unauthenticated`, `Forbidden`, `VerificationUnavailable`) so a contract needs one import and one shared `resolverLive` can serve both Siblings; the raw Cannotation stays in an interior `cannotation.ts` so `get`, `layer`, `value`, and `middleware` are not public; the Cannotation's `with` is renamed `guard` because that is the auth-specific verb, and the rpc-toolkit shape stays untouched.
