# Snapshots describe the encoded form in the toolkit's own type language

A table snapshot no longer stores Effect's `SchemaRepresentation` JSON. Each ESchema version is captured once, as its encoded side only, in the toolkit's own **snapshot type** language: string, number, boolean, null, literal, struct, array, string-keyed record, union, and a reference to another ESchema. An enum is stored as the union of its values. Two more cases are needed by existing schemas. An opaque value declared with `ESchema.fromType` is `unknown`. A recursive schema is a `recursive` binder whose back-references count binders outward, so no generated name enters a snapshot. The `_v` stamp and a value's `{ _v, _value }` envelope follow from the ESchema's kind and are not repeated in every shape. This supersedes the "Effect Schema representations" part of ADR 0001. The reason is that a snapshot guards persisted data, so its bytes must not change when Effect changes how it describes itself. A stored baseline that shifts under a dependency upgrade would fail every deploy for a reason that has nothing to do with the data.

The language lives in eschema, because eschema must refuse a field it cannot describe and cannot depend on snapshot. Snapshot capture calls the same code. As ADR 0015 set out, a conversion is allowed when its encoded side is describable, and a constructor default stays refused.

Checks are now allowed, which reverses that part of ADR 0015. They are recorded for display in Studio but never compared. A check only narrows which values are accepted and can always be relaxed again, while a changed data shape cannot be undone once rows exist. A built-in check is recorded from a small fixed catalogue with its arguments. Any other check must carry a user-supplied name through `checkAnnotation`, optionally with a description, or the field is refused. Checks are unique on their node. Checks inside a conversion belong to the conversion (`BigIntFromString` checks its string) and are neither recorded nor refused.

An `entityReference` annotation is kept on the node it describes. A changed reference is a safe change, as ADR 0008 decided.

Capture is one-way. The internal restore, which rebuilt Effect schemas from a snapshot, is removed until something needs it. The stored `TableSnapshot` document is replaced in place rather than given a new version, since no baseline worth migrating exists yet. The snapshot guard's Alchemy resource id carries a format suffix instead: bumping it makes Alchemy delete the old guard and record a fresh baseline.

Rejected: keeping Effect's representation behind a normalizing layer, because it still ties the stored bytes to Effect; treating checks as part of the frozen contract, because relaxing a check to unblock an application would then count as a breaking change; and refusing unsupported fields at capture time instead of definition time.
