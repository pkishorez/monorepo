# Adapter setup owns table-level enforcement, with no way around it

Table-level enforcement moves from a separate `table.verifySnapshot()` call into every adapter's `setup`, and nothing can skip, force, or bypass it. `setup` creates the physical table if it is missing, reads the enforcement baseline stored inside the table, diffs the table's current code-derived snapshot against it, and only then reconciles physical topology and commits the new baseline. A `breaking` or `unverifiable` change refuses with `SnapshotIncompatible` and leaves data, topology, and baseline untouched. A table that already holds rows but carries no baseline refuses with `BaselineMissing` instead of bootstrapping. Memory gains a `setup` that does nothing, so every adapter table has the same shape; a Memory table has no rows from an earlier shape to protect. The public `verifySnapshot` method is removed.

A separate call is a step a deploy can forget, and forgetting it is not a lint failure but a corrupted table: the deployed code writes rows the approved shape never described. The two paths past a refusal are a new logical table or a wipe, and both are honest about the data; `dangerouslyRemoveAllItems` takes the baseline with it so the next setup starts from nothing. Refusing a populated table without a baseline is what makes every other baseline trustworthy: enforcement never blesses a shape it did not see arrive.

The baseline is now a `TableBaseline` ESchema that holds the schema contract and two pieces of operational state that never belong in the contract: a **version floor** per registered entity, the lowest version any stored row may still carry, and the **owed backfills** enforcement accepted as `requires-backfill` and no table-wide rewrite has repaired yet. Setup floors a newly registered entity at its latest version and never raises an existing floor; it appends an owed backfill on each acceptance and prunes entries whose subject is gone. Consuming this state is Std Studio's work: a scan through `drift` and `reindex` settles both, then raises floors and clears the debt. A known floor is what will one day make retiring versions below it provably safe. Golden rows never enter the baseline; they belong to the test file (ADR 0013).

Rejected: an "I know what I am doing" flag on setup, because a flag is the same forgotten step under another name and the guarantee is worth more than the convenience; running enforcement in the serving process on first use, because it adds a consistent read and a failure mode to every cold start for a check that belongs at deploy; and treating a stale `_v` as debt, because read migration makes a row below the latest version correct by design.
