# No draft versions; the next version is the trial

ESchema once offered a **draft**: an unpublished overlay on the latest version, added with `.draft(delta, { forward, backward })`, that changed what the application saw while persisted bytes stayed at the last real version. It let a team try a field against data shaped like production without committing a version, and promote it later by turning `draft` into `evolve`. It is removed.

The draft paid for itself only when the latest version was already frozen by an approved snapshot and the developer needed to experiment against durable rows. That is not the recommended way to develop. Locally, both server and browser run on the Memory adapter, so every reload starts empty and no rows outlive an experiment; a new field is appended as the next `evolve` step and edited freely until a snapshot approves it. In production every version is a real version with a real migration. The draft sat between these two modes and served neither: it added six classes, two runtime wrappers, and a fourth type parameter on every `Any*` type, doubled the decode and encode paths, and taught a `backward` migration that silently discarded the values it stripped.

Rejected: keeping `.draft()` as an opt-in for teams that want it, because the surface area is paid by every consumer of the types; and a flag that lets an approved version be edited locally, because it would undo the one guarantee the snapshot exists to give. The cost of this decision is that a trial against a durable store now requires a version bump and a later cleanup of that version's rows, which is the point: durable stores are for shipped versions.
