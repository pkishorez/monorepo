Every physical table now declares a mode, `persistent` or `disposable`, and setup checks a Stored contract kept with the data before it changes anything (ADR 0019). `SQLite.setup`, `IDB.make`, `IDB.setup`, `D1.table`, and `DynamoDB.table` take a required `mode`. A persistent table refuses a breaking change with `SetupRefused` and is never wiped, and it can never become disposable. A disposable table is wiped on any change its stored rows cannot take. IndexedDB alone backfills: a persistent store always reindexes, and a disposable one picks `onBackfill: 'reindex' | 'wipe'`. SQLite keeps the contract in a `_std_contract` table and IndexedDB in a `_std_contract` store; both names are reserved. The snapshot guard is now the deploy guard. `DeployGuard.table(table)` guards a persistent table Alchemy does not create, such as an IndexedDB or Durable Object table. DynamoDB tables are never replaced or wiped: in either mode, a breaking change, any index change other than adding a global secondary index, or a new table name under the same resource fails the deploy. `expectTableShippable` drops `acceptBreaking`: nothing accepts a breaking change to a persistent table. Existing tables are adopted with their rows. Deploy guards get new resource ids and record a fresh Deployed contract on their next deploy; old snapshot guards are deleted.
