Add Start, which serves a routed app from a Cloudflare Worker: `@kestack/kabuki/start` gives the Document's `<Start.Head />` and `<Start.Scripts />`, and `start()` from `@kestack/kabuki/start/vite` finds the app's files by name (`src/app`, and if they are there `src/document`, `src/loaders.server`, `src/layer.server` and `src/layer.client`) and writes the Worker's and the browser's entries, so it deploys with Alchemy's `Cloudflare.Website.Vite` and no `main`. For a URL the Worker runs the Loaders of the places drawn on the server at once, draws every page from its Input with no Runtime, answers `308`, `302` and `404` as the Routes and Loaders say, keeps pages whose places are all static in the Cloudflare Cache under the build id, and serves the Loaders to the browser at `POST /_kabuki/load`. The browser hydrates from the saved History and preloads the lazy Views the server drew, which the plugin names by their module. `Router.app` now also gives its `routes`; `Route.tags` and `Router.usePending` are gone (use `usePending`); `useRouter<Route>()` and `usePending<Route>()` read the Router's Routes as the app's Route type; and the routing door no longer exports the `Place`, `PlaceSchema`, `Tag`, `Inputs`, `Wanted` and `RouterInput`, `RouterMessage`, `RouterModel` types. A page opened at a place drawn without its Input loads it once. `Start.useDrawn()` reads when and by which build the server drew the page, and whether the component asking was hydrated from it. `Route.tree` takes the root's `metadata` and the not-found Route's (`notFound`). An outlet keys each page, so a new page starts its React state afresh, and draws a client place in the browser alone, never on a server, Input or not. `Routes.place` is the Schema of every place's dotted name, and `Routes.every` and `Routes.places` give each name as that type; a missing Loader's type error names the places that need one. The Router starts loading the code of the lazy Views a move will draw together with its Inputs. In dev an edit to the app is a hot reload that carries on from its History, and under workerd the plugin scans the app's server files so the first page does not reload.
