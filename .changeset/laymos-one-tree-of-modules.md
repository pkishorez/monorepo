Laymos describes a Project as one tree. A folder with an `index.ts` is a Module, any other folder is a Wrapper for what is inside, and nothing lists them: the config is `sourceRoots`, `ignoredPaths`, `fileModules`, `rules` and `exceptions`. A Rule is a one-way permission between two paths at any depth (`"src/app": ["src/domain"]`, `"*"` for every sibling of the target); an Exception is one of the two imports no Rule can hold, a child importing its ancestor or an import against a Rule, with a mandatory `because`. `laymos lint` names each Violation's two files and the key that would hold it; `laymos inspect project` prints the tree. Layers, LayerGraphs, Module Graphs, `shared`, `exposed`, `docsPath`, `lint layers`, `lint modules` and `inspect layer` are gone, and an old config is rejected. A Change set now carries deleted paths too, and a Module whose Index was deleted reads as deleted. DevTools replaces the Layers <> Modules view with Laymo: the Project as one tree of cards that open in place, siblings ranked by their Rules, and lines that are the imports the code makes. Hovering or selecting a card lights what it uses in blue and what uses it in violet, from its own frame; the cards inside it that the outside reaches stay lit, and each is marked exposed or internal. Beside it, a Module outline and a Rule list; a right-click, or Files on a phone, opens the File list with every changed file colored, deleted files shown, and Previous and Next through the changes.
