A version whose value cannot be derived from the old row is a gap version, `evolve('v2', delta)` with no migration, and a Backfill declared on the table fills it: `.backfill(id, { entity, to, after?, run })`, where `run` gets the old value and a read-only view of every other entity. `.backfill(id, { reindex })` fills a new or changed index. Setup runs the pending Backfills before the new code serves, in one scan per entity, writing each row once, resuming after a crash; until then an old row fails with `NeedsBackfill`. `@kestack/std-toolkit/eschema` exports `NeedsBackfill`, `findNeedsBackfill` and `gapVersions`, `@kestack/std-toolkit/eschema/testing` exports `storableRows`; the adapters export `BackfillFailed`, and `@kestack/std-toolkit/db/dynamodb` exports `DynamoDB.setup`. See `docs/evolving-schema.md`.

- Breaking: a table is one declaration. Declare each entity on it before `build`, as `.entity(Task, (e) => e.primary({ pk: ['boardId'] }))` and `.singleEntity(Settings, { default })`, then any `.backfill`, and use it as `table.Task`. `table.entity(Task)…build()` and `table.singleEntity(Settings).default(…)` are gone.
- Breaking: `expectTableShippable` comes from `@kestack/std-toolkit/db/testing`, and also runs every Backfill on generated rows. `@kestack/std-toolkit/snapshot/vitest` exports only the file check, `expectSnapshotFile`.
- Breaking: the Stored contract is kept as rows inside the table on every adapter, and an old `_std_contract` is not converted. A table holding rows but no contract is refused if persistent and wiped if disposable; give a persistent table a new physical table name.
- Breaking: a persistent table refuses a change that needs a backfill, such as a new index, unless a Backfill covers it; it no longer passes with a warning. A disposable table is wiped instead. IndexedDB's `onBackfill` is removed, and `setUpFromSnapshot` is gone from `@kestack/std-toolkit/db/sqlite`.
- Breaking: `DynamoDB.table` in `@kestack/std-toolkit/alchemy` is its own resource that creates the table and runs setup at deploy, Backfills included. It takes `region`, and `credentials` or the `AWS_*` variables, and an optional `endpoint`; removing it leaves the table. `D1.table` and `DynamoDB.table` no longer add a deploy guard; `DeployGuard.table` is for an IndexedDB or Durable Object table, and refuses an index change no `{ reindex }` covers.
